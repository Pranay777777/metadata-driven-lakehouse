# v1.0.0 — a config-driven lakehouse, end to end

Onboard a new source with one control-plane row, not a new pipeline. This
release takes data from files and CDC feeds through Bronze, Silver and a
Gold star schema, with quality rules, PII masking, lineage and an audit
trail applied the same way to every source.

## Highlights

- **Configuration, not code.** A test inserts a sixth source with raw SQL —
  nothing in the code knows it exists — and it flows through Bronze and
  Silver, deduplicated.
- **Trustworthy Silver.** Deduplication, three-severity quality rules with a
  quarantine table, SCD2 history with tombstones, and keyed-HMAC masking that
  runs after quality checks and before anything is written.
- **A Gold star schema that never drops facts.** Late dimensions resolve to
  unknown members, and the dashboard counts them.
- **Observable.** Every task is audited, every job emits column-level
  lineage, and a Streamlit dashboard shows freshness against SLA, volume,
  rule pass rates, quarantine and privacy posture.
- **Migrations.** Alembic, with automatic adoption of control planes built
  before migrations existed.

## Numbers

On a 1 vCPU / 3 GB container, medians of three: the full pipeline processes
1.6M rows across five tables in **10.1 s**; Arrow is **16×** faster than
Spark at a million rows. Reproduce with `scripts/benchmark_pipeline.py` and
`scripts/benchmark_engines.py`.

## Quality

499 tests at 96% coverage. CI runs on Ubuntu (Python 3.11 and 3.12),
Windows (3.12), and against a real Postgres 14.

## Known limitations

Single-node by default; masking is the slowest stage; Bronze keeps raw PII
by design; local disk rather than object storage; Azure SQL untested; no
alerting or auth on the dashboard. See the README for the roadmap.

Twenty architecture decision records in `docs/adr/` explain every choice
above, including the three things deliberately left out.
